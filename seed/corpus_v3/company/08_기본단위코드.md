# UNT-MED-01 DICOM 창 조절과 정규화
<!--meta: doc=UNT-MED-01; doc_type=unit_code; tier=0; topic=MED; disclosure=public; stages=2차-->

## 개요
<!--meta: sec=s1; dept=AI|BE; level=신입|주니어; ct_band=하; related=PRJ-MED-3-->
루미스캔 전처리의 첫 단계입니다. 창 중심과 창 너비로 밝기 범위를 자른 뒤 0~1로 정규화합니다. 학습과 서비스가 이 함수 하나를 함께 써야 전처리가 어긋나지 않습니다.

```python
import numpy as np

def apply_window(pixels: np.ndarray, center: float, width: float) -> np.ndarray:
    """창 조절 후 0~1 정규화. 학습·서비스 공용 함수 (따로 구현 금지)."""
    low, high = center - width / 2, center + width / 2
    clipped = np.clip(pixels.astype(np.float32), low, high)
    return (clipped - low) / max(high - low, 1e-6)   # width가 0인 잘못된 태그 대비
```
프로젝트 코멘트: 창 너비 태그가 0인 영상이 실제로 있었습니다. 0으로 나누는 오류를 막는 `max(..., 1e-6)`를 지우지 마세요.

# UNT-MED-02 환자 단위 데이터 분할
<!--meta: doc=UNT-MED-02; doc_type=unit_code; tier=0; topic=MED; disclosure=public; stages=2차-->

## 개요
<!--meta: sec=s1; dept=AI|DATA; level=주니어|시니어; ct_band=중; related=PRJ-MED-3-->
같은 환자의 영상이 학습과 시험에 나뉘어 들어가지 않도록 환자 ID로 묶어 나눕니다.

```python
import random
from collections import defaultdict

def split_by_patient(records, test_ratio=0.2, seed=42):
    """records: [(image_id, patient_id), ...] -> (train_ids, test_ids)"""
    groups = defaultdict(list)
    for image_id, patient_id in records:
        groups[patient_id].append(image_id)
    patients = sorted(groups)
    random.Random(seed).shuffle(patients)
    n_test = int(len(patients) * test_ratio)
    test_p = set(patients[:n_test])
    train = [i for p in patients if p not in test_p for i in groups[p]]
    test = [i for p in test_p for i in groups[p]]
    assert not (set(train) & set(test))
    return train, test
```
프로젝트 코멘트: 영상 단위 분할로 성능이 부풀려진 일이 있었습니다. 분할 함수는 이것만 씁니다.

# UNT-DRN-01 좌표계 변환 (ENU ↔ NED)
<!--meta: doc=UNT-DRN-01; doc_type=unit_code; tier=0; topic=DRN; disclosure=public; stages=2차-->

## 개요
<!--meta: sec=s1; dept=EMB|AI|FE; level=신입|주니어; ct_band=하; related=PRJ-DRN-3-->
스카이패스의 모든 좌표 변환은 이 모듈만 씁니다. 좌표에 좌표계 이름을 붙여 다른 좌표계 값을 섞으면 바로 오류가 나게 합니다.

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Vec3:
    x: float; y: float; z: float; frame: str   # "ENU" 또는 "NED"

def enu_to_ned(v: Vec3) -> Vec3:
    if v.frame != "ENU":
        raise ValueError(f"expected ENU, got {v.frame}")
    return Vec3(x=v.y, y=v.x, z=-v.z, frame="NED")   # 축 순서와 z 부호를 함께 바꾼다

def ned_to_enu(v: Vec3) -> Vec3:
    if v.frame != "NED":
        raise ValueError(f"expected NED, got {v.frame}")
    return Vec3(x=v.y, y=v.x, z=-v.z, frame="ENU")
```
프로젝트 코멘트: y축 부호만 바꾸고 축 순서를 그대로 두어 회피 방향이 반대가 된 사고가 있었습니다. 다른 파일에서 좌표를 직접 바꾸지 마세요.

# UNT-DRN-02 텔레메트리 중복 제거와 정렬
<!--meta: doc=UNT-DRN-02; doc_type=unit_code; tier=0; topic=DRN; disclosure=public; stages=2차-->

## 개요
<!--meta: sec=s1; dept=BE; level=주니어|시니어; ct_band=중; related=PRJ-DRN-3-->
같은 일련번호의 메시지는 한 번만 받고, 기체 시각 순서로 내보냅니다.

```python
import heapq

class TelemetryBuffer:
    def __init__(self, delay_ms=200):
        self.seen, self.heap, self.delay = set(), [], delay_ms

    def push(self, drone_id: str, seq: int, t_ms: int, payload: dict) -> None:
        key = (drone_id, seq)
        if key in self.seen:          # 재전송된 메시지
            return
        self.seen.add(key)
        heapq.heappush(self.heap, (t_ms, seq, payload))

    def pop_ready(self, now_ms: int):
        out = []
        while self.heap and self.heap[0][0] <= now_ms - self.delay:
            out.append(heapq.heappop(self.heap)[2])
        return out
```
프로젝트 코멘트: `seen`은 계속 커지므로 운영 코드에서는 드론별로 최근 번호 범위만 남깁니다. 지연(delay)은 늦게 온 메시지를 기다리는 시간입니다.

# UNT-TKT-02 멱등 키로 결제 중복 막기
<!--meta: doc=UNT-TKT-02; doc_type=unit_code; tier=0; topic=TKT; disclosure=public; stages=2차-->

## 개요
<!--meta: sec=s1; dept=BE; level=주니어|시니어; ct_band=중; related=PRJ-TKT-3-->
같은 멱등 키의 요청은 한 번만 처리하고, 이후에는 저장된 결과를 돌려줍니다.

```python
def pay_once(db, idem_key: str, order_id: str, amount: int, call_pg):
    row = db.fetch_one("SELECT status, result FROM payments WHERE idem_key=%s FOR UPDATE", idem_key)
    if row and row["status"] in ("DONE", "FAILED"):
        return row["result"]                      # 이미 끝난 요청: 같은 결과
    if row and row["status"] == "PENDING":
        return {"status": "CHECKING"}             # 처리 중: 다시 보내지 않는다
    db.execute("INSERT INTO payments(idem_key, order_id, status) VALUES (%s, %s, 'PENDING')", idem_key, order_id)
    try:
        result = call_pg(order_id, amount, idem_key)
        db.execute("UPDATE payments SET status='DONE', result=%s WHERE idem_key=%s", result, idem_key)
        return result
    except TimeoutError:
        return {"status": "CHECKING"}             # 결과를 모름: 결제사 조회로 확정
```
프로젝트 코멘트: 시간 초과를 실패로 처리하면 실제로는 결제된 주문이 취소되는 일이 생깁니다.
