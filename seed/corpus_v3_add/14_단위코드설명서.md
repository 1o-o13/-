# (가상) 새벽소프트 단위 코드와 설명서

이 문서는 새벽소프트 제품 코드에서 한 가지 알고리즘만 쓰는 작은 함수를 골라 모은 것이다. 각 항목은 업무 상황을 글로 풀어 쓴 설명서와 실제로 실행되는 파이썬 코드로 이루어진다. 코딩 테스트 3번 문제를 만들 때 설명서를 검색하고, 코드는 문제 생성에 참고 자료로 넘긴다.

## UNT-A01 비행 명령 시뮬레이터 (구현/시뮬레이션)
<!--meta: doc=UNT-A01; doc_type=unit_code; tier=0; topic=DRN; dept=EMB|BE; level=신입|주니어; ct_band=하; disclosure=public; related=PRJ-DRN-3-->
### 설명서
스카이패스 드론은 비행 전에 명령 목록을 서버에서 한 번 미리 돌려 본다. 격자 지도는 행과 열로 된 문자열 목록이고, `#`은 기둥 같은 장애물이다. 명령은 U, D, L, R 네 글자이며 한 글자에 한 칸씩 움직인다. 이 밖의 글자는 잘못된 명령으로 보고 배터리 변화 없이 건너뛴다. 이동할 칸이 지도 밖이거나 장애물이면 그 명령만 건너뛰고 다음 명령을 읽는다. 한 칸 움직일 때마다 배터리가 1 줄고, 0이 되면 그 자리에서 멈춘다. 출력은 마지막 위치와 남은 배터리다.
따로 고를 알고리즘은 없고, 규칙을 순서대로 정확히 옮기는 구현 문제다. 명령 길이가 N이면 O(N)이고, N은 최대 10만이다. 명령이 비어 있으면 시작 위치와 처음 배터리를 그대로 돌려준다. 시작 배터리가 0이어도 오류 없이 처리한다. 이 코드는 행과 열을 뒤바꾸는 실수, 막힌 이동에도 배터리를 빼는 실수를 막는다.
연결 약점 태그: 구현 정확성, 경계값 처리

### 코드
```python
MOVES = {"U": (-1, 0), "D": (1, 0), "L": (0, -1), "R": (0, 1)}


def simulate(grid, start, battery, commands):
    """명령을 순서대로 실행하고 (최종 위치, 남은 배터리)를 돌려준다."""
    rows, cols = len(grid), len(grid[0]) if grid else 0
    r, c = start
    for cmd in commands:
        if battery == 0:
            break  # 배터리가 없으면 그 자리에서 멈춘다
        if cmd not in MOVES:
            continue  # 모르는 명령은 건너뛴다 (배터리 유지)
        dr, dc = MOVES[cmd]
        nr, nc = r + dr, c + dc
        # 지도 밖이거나 장애물이면 이 명령만 건너뛴다 (배터리 유지)
        if not (0 <= nr < rows and 0 <= nc < cols) or grid[nr][nc] == "#":
            continue
        r, c = nr, nc
        battery -= 1
    return (r, c), battery


if __name__ == "__main__":
    grid = ["....", ".#..", "...."]
    print(simulate(grid, (0, 0), 3, "RDDRU"))  # ((0, 2), 1)
    print(simulate(grid, (0, 0), 5, ""))       # ((0, 0), 5)
    print(simulate(grid, (0, 0), 3, "RXR"))    # ((0, 2), 1)
```

## UNT-A02 히트맵 영역 묶기 (DFS/BFS)
<!--meta: doc=UNT-A02; doc_type=unit_code; tier=0; topic=MED; dept=AI|BE; level=주니어; ct_band=중; disclosure=public; related=PRJ-MED-3-->
### 설명서
루미스캔은 분류 결과와 함께 히트맵을 보여 준다. 히트맵은 0~255 값이 담긴 2차원 격자다. 값이 기준값 이상인 칸을 관심 칸으로 보고, 상하좌우로 이어진 관심 칸을 한 영역으로 묶는다. 화면에는 영역마다 테두리 상자를 그리므로 영역 개수와 각 영역의 칸 수가 필요하다. 출력은 칸 수를 큰 순서로 정렬한 목록이다.
연결 요소를 세는 문제라서 BFS를 쓴다. 재귀 DFS는 512×512 히트맵에서 재귀 깊이 한도를 넘을 수 있어 큐 기반 BFS를 골랐다. 칸 수가 H×W일 때 시간은 O(H×W)이며, 각 칸은 큐에 한 번만 들어간다. 빈 격자나 관심 칸이 없는 격자는 빈 목록을 돌려준다. 큐에 넣을 때 방문 표시를 해야 같은 칸이 여러 번 들어가지 않는다. 이 코드는 대각선까지 이웃으로 세는 실수와 꺼낼 때 방문 표시를 하는 실수를 막는다.
연결 약점 태그: 그래프 탐색, 시간 복잡도

### 코드
```python
from collections import deque


def find_regions(heat, threshold):
    """기준값 이상 칸의 4방향 연결 영역 크기를 큰 순서로 돌려준다."""
    if not heat or not heat[0]:
        return []
    h, w = len(heat), len(heat[0])
    seen = [[False] * w for _ in range(h)]
    sizes = []
    for sr in range(h):
        for sc in range(w):
            if seen[sr][sc] or heat[sr][sc] < threshold:
                continue
            seen[sr][sc] = True  # 큐에 넣을 때 방문 표시
            q, size = deque([(sr, sc)]), 0
            while q:
                r, c = q.popleft()
                size += 1
                for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
                    if 0 <= nr < h and 0 <= nc < w and not seen[nr][nc] \
                            and heat[nr][nc] >= threshold:
                        seen[nr][nc] = True
                        q.append((nr, nc))
            sizes.append(size)
    return sorted(sizes, reverse=True)


if __name__ == "__main__":
    heat = [[200, 210, 0], [0, 0, 0], [0, 180, 190]]
    print(find_regions(heat, 150))  # [2, 2]
    print(find_regions([], 150))    # []
```

## UNT-A03 충전 거치대 위치 고르기 (완전탐색)
<!--meta: doc=UNT-A03; doc_type=unit_code; tier=0; topic=DRN; dept=BE; level=주니어; ct_band=중; disclosure=public; related=PRJ-DRN-3-->
### 설명서
스카이패스는 새 시설에 드론 충전 거치대 1대를 놓을 자리를 정한다. 입력은 거치대를 놓을 수 있는 후보 칸 목록과 점검 지점 목록이다. 거리는 격자 위 맨해튼 거리로 잰다. 목표는 가장 먼 점검 지점까지의 거리가 가장 짧은 후보를 고르는 것이다. 거리가 같은 후보가 여럿이면 목록에서 앞선 후보를 고른다. 출력은 고른 후보와 그 최대 거리다.
후보는 최대 200개, 점검 지점은 최대 500개다. 모든 후보와 지점 쌍을 다 계산해도 10만 번이라 완전탐색이 가장 단순하고 확실하다. 시간은 O(후보 수 × 지점 수)다. 후보나 점검 지점이 비어 있으면 고를 수 없으므로 None을 돌려준다. 이 코드는 최대 거리 대신 평균 거리를 비교하는 실수, 동률일 때 뒤 후보로 덮어쓰는 실수를 막는다.
연결 약점 태그: 구현 정확성, 예외 입력 처리

### 코드
```python
def pick_charger(candidates, targets):
    """가장 먼 점검 지점까지의 거리가 최소인 후보와 그 거리를 돌려준다."""
    if not candidates or not targets:
        return None
    best, best_dist = None, None
    for cr, cc in candidates:
        worst = 0
        for tr, tc in targets:
            worst = max(worst, abs(cr - tr) + abs(cc - tc))
        # 더 작을 때만 바꿔서 동률이면 앞선 후보를 유지한다
        if best_dist is None or worst < best_dist:
            best, best_dist = (cr, cc), worst
    return best, best_dist


if __name__ == "__main__":
    cands = [(0, 0), (2, 2), (4, 4)]
    pts = [(0, 4), (4, 0), (4, 4)]
    print(pick_charger(cands, pts))  # ((2, 2), 4)
    print(pick_charger([], pts))     # None
```

## UNT-A04 비행 예약 충돌 줄이기 (그리디)
<!--meta: doc=UNT-A04; doc_type=unit_code; tier=0; topic=DRN; dept=BE; level=주니어; ct_band=중; disclosure=public; related=PRJ-DRN-3-->
### 설명서
스카이패스는 한 시설 공역에 드론 1대만 띄운다. 고객사 담당자들이 비행 예약을 넣으면 시간이 겹치는 예약이 생긴다. 입력은 (시작 분, 끝 분) 목록이고, 끝 시각과 다음 시작 시각이 같으면 겹치지 않는다고 본다. 서버는 겹치지 않게 가장 많은 예약을 승인하고, 승인한 예약 목록을 돌려준다.
끝나는 시각이 빠른 예약부터 고르는 그리디를 쓴다. 일찍 끝나는 예약을 고를수록 남은 시간이 넓어지므로 이 선택이 항상 최선이다. 시작 시각 순으로 고르면 긴 예약 하나가 짧은 예약 여러 개를 막아 답이 틀린다. 정렬 때문에 O(N log N)이고 N은 하루 최대 5천 건이다. 빈 목록이면 빈 목록을 돌려준다. 끝 시각이 같으면 시작이 늦은 예약을 먼저 보도록 정렬해 결과를 일정하게 만든다. 이 코드는 끝과 시작이 같은 경계를 충돌로 처리하는 실수를 막는다.
연결 약점 태그: 그리디 판단, 경계값 처리

### 코드
```python
def approve_bookings(bookings):
    """겹치지 않게 가장 많은 비행 예약을 골라 돌려준다."""
    # 끝 시각이 빠른 순, 같으면 시작이 늦은 순
    ordered = sorted(bookings, key=lambda b: (b[1], -b[0]))
    approved = []
    last_end = float("-inf")
    for start, end in ordered:
        if start >= last_end:  # 끝 = 시작이면 겹치지 않는다
            approved.append((start, end))
            last_end = end
    return approved


if __name__ == "__main__":
    reqs = [(540, 600), (550, 560), (560, 620), (600, 660), (620, 630)]
    print(approve_bookings(reqs))  # [(550, 560), (560, 620), (620, 630)]
    print(approve_bookings([]))    # []
```

## UNT-A05 추론 영상 배치 묶기 (동적 계획법)
<!--meta: doc=UNT-A05; doc_type=unit_code; tier=0; topic=MED; dept=BE|AI; level=주니어|시니어; ct_band=상; disclosure=public; related=PRJ-MED-3-->
### 설명서
루미스캔 추론 서버는 대기 중인 X-ray 영상을 한 번에 묶어 GPU에 올린다. 영상마다 필요한 메모리(MB 단위 정수)와 우선도 점수가 있다. 한 배치의 메모리 합은 한도를 넘으면 안 된다. 목표는 한도 안에서 우선도 합이 가장 큰 영상 묶음을 고르는 것이다. 출력은 최대 우선도 합과 고른 영상 번호 목록이다.
각 영상을 넣거나 빼는 0/1 배낭 문제라서 동적 계획법을 쓴다. 우선도가 높은 순으로 담는 그리디는 큰 영상 하나가 작은 영상 여러 개를 밀어내 틀린 답을 낸다. 영상 수 N은 최대 100, 한도 M은 최대 8천이라 O(N×M) 80만 칸이면 충분하다. 고른 목록을 되짚기 위해 2차원 표를 쓴다. 영상이 없으면 (0, [])을 돌려준다. 한도가 0이면 메모리 0인 영상만 담긴다. 한도, 메모리, 우선도가 음수면 ValueError를 낸다. 이 코드는 1차원 표를 앞에서부터 갱신해 같은 영상을 두 번 담는 실수를 막는다.
연결 약점 태그: 동적 계획법, 그리디 판단

### 코드
```python
def pack_batch(items, limit):
    """items=[(메모리, 우선도)]. 한도 안 최대 우선도 합과 고른 번호를 돌려준다."""
    if limit < 0 or any(m < 0 or s < 0 for m, s in items):
        raise ValueError("한도, 메모리, 우선도는 0 이상이어야 한다")
    n = len(items)
    dp = [[0] * (limit + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        mem, score = items[i - 1]
        for cap in range(limit + 1):
            dp[i][cap] = dp[i - 1][cap]  # i번째 영상을 넣지 않음
            if mem <= cap:
                dp[i][cap] = max(dp[i][cap], dp[i - 1][cap - mem] + score)
    # 표를 거꾸로 따라가며 고른 영상을 찾는다
    picked, cap = [], limit
    for i in range(n, 0, -1):
        if dp[i][cap] != dp[i - 1][cap]:
            picked.append(i - 1)
            cap -= items[i - 1][0]
    return dp[n][limit], sorted(picked)


if __name__ == "__main__":
    imgs = [(600, 5), (300, 3), (300, 3), (400, 4)]
    print(pack_batch(imgs, 1000))  # (10, [1, 2, 3])
    print(pack_batch([], 1000))    # (0, [])
    print(pack_batch([(0, 2), (500, 4)], 0))  # (2, [0])
```

## UNT-A06 결제 요청 서버 배분 (이진 탐색)
<!--meta: doc=UNT-A06; doc_type=unit_code; tier=0; topic=TKT; dept=BE; level=주니어|시니어; ct_band=상; disclosure=public; related=PRJ-TKT-3-->
### 설명서
줄서기는 오픈 직후 결제 요청을 1초 단위 묶음으로 나눠 기록한다. 이 묶음들을 순서를 지킨 채 K대 결제 서버에 연속 구간으로 나눠 맡긴다. 한 서버가 맡는 부하는 구간 안 요청 수의 합이다. 목표는 가장 바쁜 서버의 부하를 가장 작게 만드는 것이다. 출력은 그 최소 부하 값이다.
답 X를 정하면 "최대 부하 X 이하로 K대 안에 나눌 수 있는가"는 앞에서부터 채우기로 O(N)에 확인된다. X가 커질수록 가능해지므로 답에 대해 이진 탐색을 쓴다. 탐색 범위는 가장 큰 묶음 값부터 전체 합까지다. 시간은 O(N log S)이고, N은 최대 10만, S는 최대 10^11이다. 파이썬 정수는 넘치지 않지만 다른 언어로 옮길 때는 64비트 정수가 필요하다. 서버 수 K가 0 이하면 나눌 수 없으므로 ValueError를 낸다. 묶음이 비어 있으면 0을 돌려준다. 이 코드는 하한을 0으로 잡아 한 묶음보다 작은 답을 내는 실수를 막는다.
연결 약점 태그: 이분 탐색, 오버플로·정밀도

### 코드
```python
def min_peak_load(loads, k):
    """연속 구간 k개 이하로 나눌 때 최대 구간 합의 최솟값을 돌려준다."""
    if k <= 0:
        raise ValueError("서버 수 k는 1 이상이어야 한다")
    if not loads:
        return 0

    def can_split(limit):
        servers, current = 1, 0
        for x in loads:
            if current + x > limit:
                servers += 1  # 새 서버에 맡긴다
                current = 0
            current += x
        return servers <= k

    lo, hi = max(loads), sum(loads)  # 하한은 가장 큰 묶음
    while lo < hi:
        mid = (lo + hi) // 2
        if can_split(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo


if __name__ == "__main__":
    print(min_peak_load([7, 2, 5, 10, 8], 2))  # 18
    print(min_peak_load([1, 1, 1], 5))         # 1
    print(min_peak_load([], 3))                # 0
```

## UNT-A07 연속 좌석 블록 찾기 (투 포인터/슬라이딩 윈도우)
<!--meta: doc=UNT-A07; doc_type=unit_code; tier=0; topic=TKT; dept=BE|FE; level=주니어; ct_band=중; disclosure=public; related=PRJ-TKT-3-->
### 설명서
줄서기 좌석 지도에는 "옆자리 K석 자동 찾기" 버튼이 있다. 한 줄의 좌석 상태는 문자열로 오며, `.`은 빈 좌석, `X`는 판매나 선점된 좌석, `|`는 통로다. 통로를 사이에 둔 좌석은 붙어 있지 않다고 본다. 출력은 빈 좌석 K석이 연속인 가장 왼쪽 블록의 시작 번호이고, 없으면 -1이다.
왼쪽 포인터와 오른쪽 포인터로 빈 좌석만 담는 창을 유지한다. 오른쪽이 막힌 칸을 만나면 왼쪽을 그 다음 칸으로 옮긴다. 각 칸을 한 번씩만 보므로 O(N)이고, 한 줄은 최대 2천 석이다. 매 위치마다 K칸을 다시 세는 방식은 O(N×K)라서 큰 공연장에서 느리다. K가 0 이하이거나 줄 길이보다 크면 -1을 돌려준다. 이 코드는 통로를 빈 좌석으로 세는 실수와 창 길이를 하나 덜 세는 실수를 막는다.
연결 약점 태그: 시간 복잡도, 경계값 처리

### 코드
```python
def find_block(row, k):
    """빈 좌석 k석이 연속인 가장 왼쪽 시작 번호, 없으면 -1."""
    if k <= 0 or k > len(row):
        return -1
    left = 0
    for right, seat in enumerate(row):
        if seat != ".":
            left = right + 1  # 막힌 칸 다음부터 창을 다시 시작
            continue
        if right - left + 1 == k:
            return left
    return -1


if __name__ == "__main__":
    print(find_block("..X...|..", 3))  # 3
    print(find_block("..|..", 3))      # -1
    print(find_block("....", 0))       # -1
```

## UNT-A08 판독 대기 목록 정렬 (우선순위 큐/힙)
<!--meta: doc=UNT-A08; doc_type=unit_code; tier=0; topic=MED; dept=BE; level=주니어; ct_band=중; disclosure=public; related=PRJ-MED-3-->
### 설명서
루미스캔은 AI 분석이 끝난 영상을 전문의 판독 대기 목록에 올린다. 기흉처럼 급한 소견이 의심되면 긴급도가 높게 붙는다. 영상은 계속 들어오고, 전문의가 "다음"을 누를 때마다 한 건을 꺼낸다. 순서는 긴급도가 높은 순, 같으면 먼저 들어온 순이다. 입력은 ("add", 영상ID, 긴급도)와 ("next",) 이벤트 목록이고, 출력은 꺼낸 영상ID 목록이다.
넣기와 꺼내기가 섞여 계속 일어나므로 매번 전체를 정렬하지 않고 힙을 쓴다. 한 번에 O(log N)이고, 하루 이벤트는 최대 20만 건이다. 파이썬 heapq는 최소 힙이라 긴급도에 음수를 붙인다. 같은 긴급도에서 도착 순서를 지키려고 증가하는 일련번호를 둘째 키로 넣는다. 대기 목록이 비었는데 "next"가 오면 None을 기록한다. 이 코드는 동률에서 영상ID 문자열로 비교해 도착 순서가 깨지는 실수를 막는다.
연결 약점 태그: 자료구조 선택, 예외 입력 처리

### 코드
```python
import heapq
from itertools import count


def run_worklist(events):
    """판독 대기 이벤트를 처리하고 꺼낸 영상ID 목록을 돌려준다."""
    heap, seq, popped = [], count(), []
    for ev in events:
        if ev[0] == "add":
            _, study_id, urgency = ev
            # 긴급도 높은 순, 같으면 도착 순 (일련번호)
            heapq.heappush(heap, (-urgency, next(seq), study_id))
        elif ev[0] == "next":
            popped.append(heapq.heappop(heap)[2] if heap else None)
    return popped


if __name__ == "__main__":
    evs = [("add", "S1", 1), ("add", "S2", 3), ("add", "S3", 3),
           ("next",), ("add", "S4", 5), ("next",), ("next",),
           ("next",), ("next",)]
    print(run_worklist(evs))  # ['S2', 'S4', 'S3', 'S1', None]
```

## UNT-A09 결제 재시도 중복 막기 (해시)
<!--meta: doc=UNT-A09; doc_type=unit_code; tier=0; topic=TKT; dept=BE; level=신입|주니어; ct_band=하; disclosure=public; related=PRJ-TKT-3-->
### 설명서
줄서기 결제 화면은 응답이 늦으면 같은 결제를 다시 보낸다. 요청마다 멱등 키가 붙어 있고, 같은 키는 한 번만 결제해야 한다. 입력은 (멱등 키, 금액) 요청 목록이다. 처음 본 키는 결제하고, 이미 본 키는 처음 결과를 그대로 돌려준다. 같은 키인데 금액이 다르면 위조나 버그로 보고 "거절"로 처리한다. 출력은 요청마다 "결제", "중복", "거절" 중 하나다.
키를 이미 봤는지 빠르게 찾아야 하므로 딕셔너리를 쓴다. 조회와 저장이 평균 O(1)이라 전체 O(N)이고, 오픈 직후 초당 2천 건도 처리한다. 목록에서 매번 찾으면 O(N^2)이 되어 요청이 몰릴 때 느려진다. 키가 빈 문자열이거나 None이면 멱등 처리가 불가능하므로 "거절"한다. 이 코드는 금액이 다른 재요청을 중복으로 통과시키는 실수를 막는다.
연결 약점 태그: 자료구조 선택, 예외 입력 처리

### 코드
```python
def process_payments(requests):
    """멱등 키 기준으로 결제 요청을 처리하고 결과 목록을 돌려준다."""
    seen = {}  # 멱등 키 -> 처음 금액
    results = []
    for key, amount in requests:
        if not key:
            results.append("거절")  # 키가 없으면 멱등 처리 불가
        elif key not in seen:
            seen[key] = amount
            results.append("결제")
        elif seen[key] == amount:
            results.append("중복")
        else:
            results.append("거절")  # 같은 키, 다른 금액
    return results


if __name__ == "__main__":
    reqs = [("k1", 77000), ("k2", 99000), ("k1", 77000),
            ("k1", 1000), ("", 5000)]
    print(process_payments(reqs))  # ['결제', '결제', '중복', '거절', '거절']
```

## UNT-A10 격자 경로 계획 (최단 경로(다익스트라))
<!--meta: doc=UNT-A10; doc_type=unit_code; tier=0; topic=DRN; dept=BE; level=주니어|시니어; ct_band=상; disclosure=public; related=PRJ-DRN-3-->
### 설명서
스카이패스 경로 계획 서비스는 시설 격자 지도 위에서 출발 칸부터 목표 칸까지 비행 경로를 짠다. 각 칸에는 통과 비용이 정수로 적혀 있다. 좁은 통로나 사람이 많은 구역은 비용이 크고, 0은 들어갈 수 없는 칸이다. 상하좌우로만 움직이며, 경로 비용은 들어간 칸들의 비용 합이다. 출력은 최소 비용이고, 갈 수 없으면 -1이다.
칸마다 비용이 달라 BFS로는 최단을 보장하지 못하므로 다익스트라를 쓴다. 비용이 모두 양수라 음수 간선 문제는 없다. 칸 수 V가 최대 25만일 때 힙을 써서 O(V log V)다. 힙에서 꺼낸 값이 이미 기록한 거리보다 크면 오래된 항목이라 건너뛴다. 출발 칸이 막혀 있으면 바로 -1을 돌려주고, 출발과 목표가 같으면 0이다. 이 코드는 출발 칸 비용을 합에 넣는 실수와 오래된 힙 항목을 다시 펼치는 실수를 막는다.
연결 약점 태그: 최단 경로, 시간 복잡도

### 코드
```python
import heapq


def plan_route(cost, start, goal):
    """통과 비용 격자에서 start→goal 최소 비용, 불가능하면 -1."""
    h, w = len(cost), len(cost[0])
    sr, sc = start
    if cost[sr][sc] == 0 or cost[goal[0]][goal[1]] == 0:
        return -1
    dist = [[float("inf")] * w for _ in range(h)]
    dist[sr][sc] = 0  # 출발 칸 비용은 넣지 않는다
    heap = [(0, sr, sc)]
    while heap:
        d, r, c = heapq.heappop(heap)
        if d > dist[r][c]:
            continue  # 오래된 항목
        if (r, c) == goal:
            return d
        for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
            if 0 <= nr < h and 0 <= nc < w and cost[nr][nc] > 0:
                nd = d + cost[nr][nc]
                if nd < dist[nr][nc]:
                    dist[nr][nc] = nd
                    heapq.heappush(heap, (nd, nr, nc))
    return -1


if __name__ == "__main__":
    grid = [[1, 9, 1], [1, 0, 1], [1, 1, 1]]
    print(plan_route(grid, (0, 0), (0, 2)))  # 6
    print(plan_route([[1, 0, 1]], (0, 0), (0, 2)))  # -1
```

## UNT-A11 점검 구역 묶기 (Union Find)
<!--meta: doc=UNT-A11; doc_type=unit_code; tier=0; topic=DRN; dept=BE; level=주니어; ct_band=중; disclosure=public; related=PRJ-DRN-3-->
### 설명서
스카이패스는 시설을 여러 점검 구역으로 나눠 관리한다. 두 구역 사이에 드론이 지날 수 있는 통로가 있으면 한 번의 비행으로 함께 점검할 수 있다. 시설 관리자는 통로 정보를 하나씩 추가 입력한다. 서버는 통로가 추가될 때마다 비행 묶음 개수를 다시 알려 줘야 한다. 입력은 구역 수 N과 (구역 a, 구역 b) 통로 목록이고, 출력은 통로를 하나씩 더할 때마다의 묶음 개수 목록이다.
간선이 계속 추가되고 연결 여부만 알면 되므로 Union Find를 쓴다. 매번 BFS를 다시 돌리면 O(E×(N+E))지만, 경로 압축과 크기 기준 합치기를 쓰면 거의 O(E)다. N은 최대 10만, 통로는 최대 20만 개다. 이미 같은 묶음인 두 구역 사이 통로는 개수를 줄이지 않는다. 자기 자신으로 가는 통로도 오류 없이 무시한다. 이 코드는 대표를 찾지 않고 부모끼리 바로 합쳐 묶음이 어긋나는 실수를 막는다.
연결 약점 태그: 자료구조 선택, 그래프 탐색

### 코드
```python
def count_groups(n, passages):
    """통로를 하나씩 더할 때마다 남은 비행 묶음 개수를 돌려준다."""
    parent = list(range(n))
    size = [1] * n

    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]  # 경로 압축
            x = parent[x]
        return x

    groups, history = n, []
    for a, b in passages:
        ra, rb = find(a), find(b)
        if ra != rb:
            if size[ra] < size[rb]:
                ra, rb = rb, ra
            parent[rb] = ra  # 작은 쪽을 큰 쪽 아래로
            size[ra] += size[rb]
            groups -= 1
        history.append(groups)
    return history


if __name__ == "__main__":
    print(count_groups(5, [(0, 1), (1, 2), (0, 2), (3, 3), (3, 4)]))
    # [4, 3, 3, 3, 2]
```

## UNT-A12 대기열 입장 순서 정하기 (정렬)
<!--meta: doc=UNT-A12; doc_type=unit_code; tier=0; topic=TKT; dept=BE; level=신입|주니어; ct_band=하; disclosure=public; related=PRJ-TKT-3-->
### 설명서
줄서기 대기열은 평소 Redis 정렬된 집합으로 순서를 관리한다. 장애 복구나 점검 때는 저장된 접속 기록으로 입장 순서를 다시 계산한다. 입력은 (사용자ID, 진입 시각 밀리초, 차단 여부) 목록이다. 차단된 사용자는 빼고, 같은 사용자가 여러 번 들어왔으면 가장 이른 진입 시각 하나만 쓴다. 순서는 진입 시각이 빠른 순이고, 같으면 사용자ID 사전 순이다. 출력은 앞에서 K명의 사용자ID 목록이다.
조건이 정해진 순서 매기기라서 정렬을 쓴다. 중복을 먼저 줄인 뒤 (시각, ID) 키로 한 번 정렬하므로 O(N log N)이고, N은 최대 50만 건이다. 동률 기준을 키에 넣어야 실행할 때마다 같은 결과가 나온다. 입력이 비거나 K가 0이면 빈 목록이다. 이 코드는 재접속 기록을 따로 세어 한 사람이 두 자리를 차지하는 실수를 막는다.
연결 약점 태그: 구현 정확성, 입출력 처리

### 코드
```python
def admission_order(records, k):
    """차단 제외, 사용자별 최초 진입 기준으로 앞 k명을 돌려준다."""
    first_seen = {}
    blocked = set()
    for user, ts, is_blocked in records:
        if is_blocked:
            blocked.add(user)
        if user not in first_seen or ts < first_seen[user]:
            first_seen[user] = ts  # 재접속은 가장 이른 시각만
    entries = [(ts, user) for user, ts in first_seen.items()
               if user not in blocked]
    entries.sort()  # 시각 오름차순, 같으면 ID 사전 순
    return [user for _, user in entries[:max(k, 0)]]


if __name__ == "__main__":
    recs = [("u3", 1000, False), ("u1", 1000, False), ("u2", 900, True),
            ("u3", 800, False), ("u4", 1200, False)]
    print(admission_order(recs, 3))  # ['u3', 'u1', 'u4']
    print(admission_order([], 3))    # []
```

## UNT-A13 증강 기법 조합 고르기 (백트래킹)
<!--meta: doc=UNT-A13; doc_type=unit_code; tier=0; topic=MED; dept=AI; level=주니어|시니어; ct_band=상; disclosure=public; related=PRJ-MED-3-->
### 설명서
루미스캔 학습 파이프라인은 데이터 증강 기법을 조합해 쓴다. 기법마다 에폭당 추가 시간(분)과 검증에서 얻은 기대 점수가 있다. 함께 쓰면 안 되는 쌍도 있다. 크게 자르기와 큰 각도 회전을 같이 쓰면 폐 끝과 늑골 횡격막각이 잘려 기흉·흉수 소견이 사라지는 식이다. 좌우 반전은 심장이 오른쪽에 오는 해부학적으로 맞지 않는 영상을 만들어 처음부터 후보에서 뺀다. 입력은 기법 목록, 금지 쌍, 시간 예산이다. 출력은 예산 안에서 금지 쌍 없이 점수 합이 최대인 조합이다.
기법은 최대 20개이고 금지 쌍 때문에 단순 배낭 표로 풀기 어렵다. 그래서 기법을 하나씩 넣거나 빼며 탐색하는 백트래킹을 쓴다. 시간 예산을 넘거나 금지 쌍이 생기면 그 가지를 바로 자른다. 최악은 O(2^N)이지만 가지치기로 실제 탐색 수는 훨씬 적다. 기법이 없으면 점수 0과 빈 조합을 돌려준다. 이 코드는 되돌아올 때 고른 목록에서 빼지 않아 조합이 섞이는 실수를 막는다.
연결 약점 태그: 시간 복잡도, 구현 정확성

### 코드
```python
def best_augments(augs, banned, budget):
    """augs=[(이름, 분, 점수)]. 예산·금지 쌍을 지키는 최고 점수 조합."""
    ban = {frozenset(p) for p in banned}
    best = [0, []]
    chosen = []

    def dfs(i, used, score):
        if score > best[0]:
            best[0], best[1] = score, list(chosen)
        for j in range(i, len(augs)):
            name, minutes, gain = augs[j]
            if used + minutes > budget:
                continue  # 예산 초과 가지 자르기
            if any(frozenset((name, c)) in ban for c in chosen):
                continue  # 금지 쌍 가지 자르기
            chosen.append(name)
            dfs(j + 1, used + minutes, score + gain)
            chosen.pop()  # 되돌리기

    dfs(0, 0, 0)
    return best[0], best[1]


if __name__ == "__main__":
    augs = [("crop", 2, 5), ("rotate20", 3, 4), ("contrast", 2, 3),
            ("noise", 4, 4)]
    print(best_augments(augs, [("crop", "rotate20")], 8))
    # (12, ['crop', 'contrast', 'noise'])
    print(best_augments([], [], 8))  # (0, [])
```

## UNT-A14 매크로 의심 요청 창 (누적 합)

### 설명서
줄서기 데이터팀은 매크로 의심 계정을 고르는 첫 규칙으로 요청 밀도를 본다. 한 계정의 초 단위 요청 수 배열이 길이 T로 주어지며, 오픈 후 0초부터 T-1초까지에 해당한다. 길이 W초인 어떤 구간에서든 요청 합이 기준값 이상이면 의심 계정으로 표시한다. 출력은 의심 여부와 처음 기준을 넘은 구간의 시작 초다. 넘지 않으면 (False, -1)이다.
구간 합을 매번 다시 더하면 O(T×W)다. 누적 합 배열을 한 번 만들면 어떤 구간 합도 빼기 한 번으로 구하므로 O(T)다. T는 최대 3600초, 계정은 수십만 개라서 이 차이가 크다. 누적 합 배열은 길이를 T+1로 두고 0을 앞에 넣어 경계 계산을 단순하게 한다. W가 T보다 길면 전체 합 하나로 판단한다. 배열이 비었거나 W가 0 이하면 (False, -1)이다. 이 코드는 구간 끝 번호를 하나 어긋나게 빼는 실수를 막는다.
연결 약점 태그: 시간 복잡도, 경계값 처리

### 코드
```python
def flag_macro(counts, window, threshold):
    """길이 window 구간 합이 threshold 이상인 첫 시작 초를 찾는다."""
    if not counts or window <= 0:
        return False, -1
    prefix = [0] * (len(counts) + 1)  # prefix[i] = counts[:i] 합
    for i, c in enumerate(counts):
        prefix[i + 1] = prefix[i] + c
    w = min(window, len(counts))
    for start in range(len(counts) - w + 1):
        if prefix[start + w] - prefix[start] >= threshold:
            return True, start
    return False, -1


if __name__ == "__main__":
    per_sec = [1, 0, 2, 9, 8, 7, 0, 1]
    print(flag_macro(per_sec, 3, 20))  # (True, 3)
    print(flag_macro(per_sec, 3, 30))  # (False, -1)
    print(flag_macro([], 3, 1))        # (False, -1)
```

## UNT-A15 배포 작업 순서 정하기 (위상 정렬)
<!--meta: doc=UNT-A15; doc_type=unit_code; tier=0; topic=COMMON; dept=BE; level=주니어; ct_band=중; disclosure=public-->
### 설명서
새벽소프트 공통 배포 도구는 서비스 배포를 작은 작업으로 나눠 실행한다. 데이터베이스 변경은 서버 배포보다 먼저, 서버 배포는 화면 배포보다 먼저 끝나야 하는 식의 선후 관계가 있다. 입력은 작업 이름 목록과 (먼저 할 작업, 나중 할 작업) 쌍 목록이다. 출력은 모든 관계를 지키는 실행 순서다. 순환이 있으면 배포를 멈추고 None을 돌려준다.
선후 관계 그래프에서 순서를 뽑는 문제라서 진입 차수 기반 위상 정렬을 쓴다. 들어오는 간선이 없는 작업부터 꺼내고, 꺼낸 작업이 가리키는 작업의 차수를 줄인다. 같은 시점에 여러 작업이 가능하면 이름 순으로 꺼내 결과를 항상 같게 만든다. 이를 위해 힙을 쓰며 O((V+E) log V)다. 작업은 최대 5천 개다. 꺼낸 작업 수가 전체보다 적으면 순환이다. 작업이 없으면 빈 목록을 돌려준다. 이름이 중복되거나 관계에 목록에 없는 작업이 나오면 ValueError를 낸다. 이 코드는 순환을 놓치고 일부 작업만 배포하는 실수를 막는다.
연결 약점 태그: 그래프 탐색, 예외 입력 처리

### 코드
```python
import heapq


def deploy_order(tasks, deps):
    """선후 관계를 지키는 실행 순서. 순환이 있으면 None."""
    if len(set(tasks)) != len(tasks):
        raise ValueError("작업 이름이 중복됨")
    indeg = {t: 0 for t in tasks}
    nxt = {t: [] for t in tasks}
    for before, after in deps:
        if before not in indeg or after not in indeg:
            raise ValueError(f"모르는 작업: {before} -> {after}")
        nxt[before].append(after)
        indeg[after] += 1
    ready = [t for t in tasks if indeg[t] == 0]
    heapq.heapify(ready)  # 같은 시점이면 이름 순
    order = []
    while ready:
        t = heapq.heappop(ready)
        order.append(t)
        for u in nxt[t]:
            indeg[u] -= 1
            if indeg[u] == 0:
                heapq.heappush(ready, u)
    return order if len(order) == len(tasks) else None  # 순환 검사


if __name__ == "__main__":
    tasks = ["db", "api", "web", "cache"]
    deps = [("db", "api"), ("api", "web"), ("cache", "api")]
    print(deploy_order(tasks, deps))  # ['cache', 'db', 'api', 'web']
    print(deploy_order(["a", "b"], [("a", "b"), ("b", "a")]))  # None
```

## UNT-A16 소견 불일치 집계 (비트마스킹)
<!--meta: doc=UNT-A16; doc_type=unit_code; tier=0; topic=MED; dept=AI|BE; level=주니어; ct_band=중; disclosure=public; related=PRJ-MED-3-->
### 설명서
루미스캔은 이상 소견 5종(결절, 폐렴성 음영, 기흉, 흉수, 심비대)을 분류한다. 품질 점검에서는 AI 결과와 전문의 최종 판독을 영상마다 비교한다. 각 결과는 0~31 정수로 저장되며, 비트 0부터 4가 소견 5종의 유무다. 입력은 (AI 값, 전문의 값) 쌍 목록이다. 출력은 소견별로 AI만 표시한 건수(과검출)와 전문의만 표시한 건수(놓침)다.
소견이 5개뿐이라 집합 대신 비트 연산이 가볍고 빠르다. `ai & ~doc`는 과검출, `doc & ~ai`는 놓침을 한 번에 구한다. 영상 수가 N이면 O(5N)이고, 하루 최대 3만 건이다. 저장 오류로 0~31 밖 값이 들어오면 그 쌍은 건너뛰고 건너뛴 수를 함께 돌려준다. 빈 목록이면 모든 건수가 0이다. 이 코드는 비트 번호와 소견 이름을 다른 순서로 대응시키는 실수, 파이썬 음수 비트 연산에서 범위 밖 비트가 섞이는 실수를 막는다.
연결 약점 태그: 구현 정확성, 예외 입력 처리

### 코드
```python
FINDINGS = ["결절", "폐렴성 음영", "기흉", "흉수", "심비대"]  # 비트 0~4
FULL = (1 << len(FINDINGS)) - 1  # 0b11111


def mismatch_report(pairs):
    """소견별 과검출·놓침 건수와 건너뛴 쌍 수를 돌려준다."""
    over = [0] * len(FINDINGS)
    miss = [0] * len(FINDINGS)
    skipped = 0
    for ai, doc in pairs:
        if not (0 <= ai <= FULL and 0 <= doc <= FULL):
            skipped += 1  # 범위 밖 값은 건너뛴다
            continue
        only_ai = ai & ~doc & FULL
        only_doc = doc & ~ai & FULL
        for bit in range(len(FINDINGS)):
            over[bit] += (only_ai >> bit) & 1
            miss[bit] += (only_doc >> bit) & 1
    return {"과검출": dict(zip(FINDINGS, over)),
            "놓침": dict(zip(FINDINGS, miss)), "건너뜀": skipped}


if __name__ == "__main__":
    data = [(0b00101, 0b00100), (0b00000, 0b10000), (40, 1)]
    print(mismatch_report(data))
    # 과검출: 결절 1, 놓침: 심비대 1, 건너뜀 1
```
