# (가상) 새벽소프트 문서 메타데이터 규격 — 6.1 화상면접용

영찬님 `seed/corpus_v3/META_SPEC.md`(v0.3)와 **형식·조건이 같다** (같은 로더 `scripts/load_corpus.py`로 적재). **내용(회사 업무·프로젝트)만 다르다.**
기존 `seed/corpus_v3`·`seed/corpus_alt`는 건드리지 않는다. 확정되면 `tasks.ps1 seed`의 적재 폴더만 이 폴더로 바꾼다.

## 회사

(가상) 새벽소프트 — 자사 커머스 플랫폼 **새벽마켓**을 직접 만들고 운영하는 IT 기업 한 곳.
온라인 쇼핑(웹·앱), 결제(온라인 + 매장 결제 단말), 검색·추천, 고객 상담, 데이터 플랫폼, 물류센터 설비까지 **한 서비스를 이루는 프로젝트 6개**를 부서들이 나눠 진행한다.
직무: 백엔드(BE), 프론트엔드(FE), ML 엔지니어(AI), 데이터 엔지니어(DATA), 임베디드(EMB).

## 형식 (v0.3과 같음)

```
# 문서 제목
<!--meta: doc=PRJ-PAY-3; doc_type=project; tier=3; topic=PAY; disclosure=public; status=done; stages=1차|2차-->

## 섹션 제목
<!--meta: sec=s1; dept=BE|FE; level=신입|주니어; ct_band=하; related=INC-PAY-01-->
<!--forbid: 단어1|단어2-->
본문
```

- 청크 1개 = `##` 섹션 1개, 청크 ID = `doc#sec`. 임베딩 머리말 `[새벽소프트 | 문서 제목 | 난이도 | 부서 | 섹션 제목]`.
- 파일은 문서 종류별 11개 (01–12, 10과 11은 한 파일). tier·doc_type·status·doc ID 규칙은 v0.3과 같다.

## 면접에서 쓰는 방식 (6.1)

1. 지원 직무(dept)로 프로젝트 후보를 거른다.
2. 이력서 기술과 가장 비슷한 프로젝트 **1개**를 검색(RAG)으로 고른다. 3~10번 기술 질문은 모두 이 프로젝트 문서를 근거로 한다.
3. 3번 = 코딩 약점 × 이 프로젝트, 4번 = 3번 꼬리질문(40점 미만·무응답이면 재질문).
4. 5~10번 = 이 프로젝트의 본 질문 → 꼬리질문 → 다음 섹션 본 질문.
5. 최종 평가에 근거 프로젝트, **적합성**(지금 이 프로젝트에 투입 가능), **확장성**(다른 프로젝트로 옮겨도 가능) 의견을 남긴다. 점수에는 넣지 않는다.

## 분량 조건 (v0.3 "10문항 면접 대비" 규칙을 프로젝트 1개 기준으로 강화)

프로젝트 1개만으로 3~10번 8문항이 바닥나지 않게 한다.

| 조건 | 기준 |
| --- | --- |
| 3급 기술 섹션 | 프로젝트 × 부서 × 난이도(하·중·상)마다 **4개 이상** (섹션 하나에 부서 여러 개 가능) |
| 2급 (꼬리 1) | 3급 섹션마다 related로 이어지는 2급 project·incident·open_issue·test_result가 1개 이상 |
| 1급 (꼬리 2) | 2급 문서마다 related로 이어지는 1급 project·research가 1개 이상 |
| 코딩 연계 | 프로젝트마다 코딩 약점 알고리즘(BFS·DP·그리디·이분 탐색·투 포인터·다익스트라·위상 정렬 등)이 들어간 3급 섹션이 난이도별 1개 이상 |
| 개요(sec=ov) | 대체용, 개수에 넣지 않음 |

실제 분량 (2026-11-06): **프로젝트마다 70청크, 전체 434청크** (6 × 70 + 공통 14, 영찬님 약 245청크). 부서가 2개뿐이던 레이크하우스에 AI, 스토어프론트에 DATA를 더해 70을 채웠다.
