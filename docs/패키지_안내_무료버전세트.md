# AI 채용 솔루션 · 무료 버전 세트 (2026-11-01)

유료 API(Claude·OpenAI)를 빼고, LLM·임베딩까지 모두 온프레미스 무료 모델로 바꾼 세트.
유료판은 지우지 않고 `requirements/paid/`와 `유료버전_정리.md`에 따로 보관.

## 모델 (전부 무료·상업 사용 가능 라이선스)
| 기능 | 무료 모델 | 라이선스 | 실행 |
| --- | --- | --- | --- |
| 면접 질문·꼬리질문·판정, 서류 적합도, 코딩 문제 생성·난이도 보정 | Qwen3 4B (`qwen3:4b`, 약 2.5GB, 팀원 B와 같은 모델) | Apache 2.0 | Ollama, GPU |
| 30초 대체, 평가 근거 검증(평가와 다른 모델), 챗봇·장애 원인 | Qwen3 1.7B (`qwen3:1.7b`, 약 1.4GB) | Apache 2.0 | Ollama, GPU |
| FAQ 임베딩 | bge-m3 (1024차원) → 한국어 개선 시 KURE-v1 (같은 1024차원) | MIT | Ollama |
| STT | faster-whisper large-v3-turbo | MIT | 변경 없음 |
| 얼굴 대조·감지, TTS, 채점, 표절 | DeepFace+ArcFace, MediaPipe, Supertonic 1.3.1(면접관 음성, 팀원 B), Judge0 1.13.1, rapidfuzz | 무료 | 11/4 TTS를 Supertonic으로 |

LLM 서버: Ollama 0.40.12 (`compose.ollama.yml`, 팀원 B 기준 버전, qwen3는 0.6.6 이상)

## 바뀐 것 (유료판 대비)
- (11/4) 팀원 B 목록(10/30)에 맞춤: 테스트 LLM qwen3:4b·qwen3:1.7b, Ollama 0.40.12, numpy 2.5.4(api·stt·face·tts), 화면 Next.js 16.4.3(Node 24, `requirements/frontend.package.json` = 팀원 B 그대로), 면접관 음성 Supertonic 1.3.1(`requirements/tts.*` = 팀원 B 그대로), redis:8.2, pgvector/pgvector:0.8.7-pg17. numpy 외 버전 변화 0건 확인 후 적용
- api: (11/4) 운영 LLM = Claude Sonnet 5.5·Haiku 5.5로 결정. langchain-anthropic 1.7.7(+anthropic 2.3.0 등 4개, 유료판 검증 버전 그대로)을 기본 목록에 추가, 다른 버전 변경 없음 → `.env`만 바꿔 전환. 모델 연결은 `app_6_1/llm.py` 한 곳
- api: (11/2) 엑셀 내보내기 openpyxl 제거(팀 결정: PDF만). langchain·langgraph는 다른 파트용으로 유지(6.1은 없어도 동작 확인)
- api: `langchain-anthropic`, `langchain-openai`와 딸린 anthropic·openai·tiktoken·jiter·docstring-parser 제거(7개) → `langchain-ollama 1.1.0`, `ollama 0.6.3` 추가. 나머지 123개 버전 그대로
- DB: `faq.embedding` vector(1536) → **vector(1024)**, `interview_setting.llm_provider`에 `ollama` 추가(기본값), 기본 모델 qwen3:4b / qwen3:1.7b
- 설정: `.env.example` (LLM_PROVIDER=ollama). 코드는 provider만 바꾸면 유료판으로 전환

## 검증 (Python 3.12)
- 버전 해석: api 127개 충돌 0건(11/2 엑셀 제거, 11/4 Claude 연결 4개 추가, 기존 버전 변경 없음), 설치 후 호환 확인, stt·face와 공유 26개 버전 불일치 0건
- 실행 시험 `scripts/test_full_stack.py`: 17 통과 (GPU 패키지 1개는 GPU 서버용이라 건너뜀)
  - Ollama 판정 JSON 스키마, 30초 대체·60초 오류 규칙, LangGraph, 임베딩 1024 → pgvector 실제 검색
- DB `db/`: 10 통과 (전체 흐름 + 위반 30건 + 1024차원만 받음)
- 모델 파일 실제 실행은 이 작업 환경에서 내려받기가 막혀 있어 미실행 → GPU 서버/내 PC에서 `scripts/check_ollama.py`

## 설치·점검
```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements/api.lock.txt -r requirements/dev.in
pytest -q scripts/test_full_stack.py db/
docker compose -f compose.ollama.yml up -d     # GPU 서버
python scripts/check_ollama.py                 # 내 PC(GTX 1660 SUPER 6GB)에서도 기본값으로 됨
```

## 모델 전환 (`app_6_1/llm.py`, 시험 `app_6_1/test_llm_switch.py` 13개)
- 테스트 Ollama ↔ 운영 Claude를 `.env`만 바꿔 전환. 같은 시험을 두 제공사로 돌려 판정 형식·30초 대체·60초 오류가 똑같이 동작함을 확인
- 시작 때 검사: 제공사 이름, 모델 두 개, 평가≠빠른 모델, API 키, 모델 이름 오타(연결 시험)
- 진행 중인 면접은 DB에 저장한 모델 유지, 새 면접부터 적용
- 발견: Claude 5.5는 temperature 설정을 거부 → Claude에는 넣지 않음

## 6.1 혼자 개발용 가짜 모듈 (`stubs_6_1/`, 11/11 통합 때 진짜로 교체)
- `contracts.py`: 주고받는 형식 (TRD 6장 I-1·I-4·I-5). 진짜 모듈도 이 형식을 지키면 그대로 끼워짐
- `fake_modules.py`: 1·2번 인성 질문(회사 질문 은행에서 고름), 3번부터 기술 질문(회사 문서 RAG 결과 × 이력서)·꼬리질문·되묻기(I-1), 답변 판정(I-4), 최종 평가·검사 1~4(I-5) 대신. LLM 없이 늘 같은 결과
- `app_6_1/flow.py`: 진행 규칙 `next_action` (인성은 판정만 / 기술 우수 → 꼬리질문 깊이 ≤2 / 미흡 → 되묻기 1번 / 10문항이면 종료)
- `seed_6_1.sql`: 시험 공고·지원자 (I-3 대신) + 인성 질문 은행 3개 + 회사 문서 1조각
- 시험: `pytest -q stubs_6_1/` → 13 통과 (진행 규칙 + 면접 10문항을 가짜 모듈로 끝까지 돌려 실제 DB 규칙 통과 확인)
- 임시 산식(비언어 등)은 팀 미정 사항이라 진짜 채점 엔진이 오면 바뀜

## 주의
- GPU 서버에 STT·얼굴·qwen3(4B+1.7B)·bge-m3가 같이 올라감 → 동시 10명 대기 ≤60초는 11/11~16에 측정, 모자라면 24GB 또는 LLM 전용 GPU
- 무료 모델 판정 품질은 유료보다 낮을 수 있음 → 판정 일치율 ≥80% 기준으로 같이 측정
- 한국어 품질: qwen3 4B는 작은 모델이라 판정 품질이 낮을 수 있음 → 실제 면접 답변으로 확인(일치율 ≥80%), 운영은 Claude
- qwen3는 생각(thinking) 모드가 있어 응답이 길어질 수 있음 → check_ollama.py로 30초 규칙 확인
- langchain-postgres는 한 프로세스에서 임베딩 차원 하나만 씀 (1024 고정)
- 문자 발송·휴대폰 본인인증(CI)은 모델이 아니라 유료 외부 서비스 → `유료버전_정리.md`, 개발 중엔 가짜 연동
