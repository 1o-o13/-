# 1. 개요
화상 면접은 본인 확인 → 비기술 2문항 → 기술 8문항(꼬리질문·재질문 포함) → 답변별 점수 → 최종 평가·검증 → 담당자 확정을 서버에서 끝까지 돌리는 구조입니다. 기술 질문은 회사 문서를 검색해 근거를 찾고, 답변 점수에 따라 더 깊이 묻거나 다음 주제로 넘어갑니다. 영상과 얼굴 사진은 저장하지 않고, 답변 음성은 텍스트로 바꾼 뒤 바로 지웁니다.

**범위:** 2차 응시 안내(CAN-008) → 사전 점검·본인 확인·동의(CAN-009) → 코딩 뒤 안내(CAN-011) → 면접 진행(CAN-012) → 응시 완료(CAN-013) → AI 최종 평가·검증 → 담당자 확인(ADM-033). 응시 앞뒤 흐름을 끝까지 시험하려고 채용 사이트·1차 서류·코딩 테스트·최종 합격 결정도 6.1에서 임시로 만들었고, 다른 파트 정식 구현이 오면 바꿉니다. {변경 11/11}

**코드 위치:** `api/`(FastAPI·그래프·LLM 관문), `worker/`(Celery), `web/`(Next.js), `stt/`·`tts/`·`face/`·`nli/`·`judge/`(모델·채점 컨테이너), `db/interview_schema.sql`(면접 테이블), `app_6_1/`(진행 규칙·모델 연결), `stubs_6_1/`(형식·가짜 모듈), `seed/`(시험 데이터·회사 문서), `scripts/`(적재·측정·문서), `records/`(시험·측정 기록).

# 4. 면접 흐름과 질문 구성
| 번호 | 종류 | 근거 | 점수 | 이어지는 질문 |
|---|---|---|---|---|
| 1 | 비기술 | 이력서 경험 + 인계 데이터의 확인 포인트 | 없음 (의견) | 없음 |
| 2 | 비기술 | 인계 데이터의 결핍 가치 (인재상 문서) | 없음 (의견) | 없음 |
| 3 | 기술 | 코딩 약점 요약 + 회사 문서 | 0~100 | 있음 |
| 4~10 | 기술 | 앞 주제의 꼬리질문·재질문, 또는 다음 주제 본 질문 | 0~100 | 있음 |

## 진행 규칙 (`next_action`)
| 상황 | 다음 |
|---|---|
| 10번째 답변 판정이 끝남 | 종료 |
| 1·2번 비기술 질문 | 의견만 남기고 다음 질문 |
| 응답 상태가 ok가 아님 (무응답·STT 없음·시간 초과·형식 오류) | 다음 주제 (기술이면 0점) |
| 70점 이상, 깊이 < 2, 관련성 ≥ 0.4 | 꼬리질문 (깊이 +1). 새 꼬리 체인은 면접 전체에서 2개 주제까지 {변경 11/9} |
| 70점 이상인데 관련성 < 0.4, 이 주제에서 재질문 안 함 | 재질문 (범위를 좁혀 같은 깊이) {신규 11/9} |
| 본 질문 40점 미만, 이 주제에서 재질문 안 함 | 재질문 1번 (같은 근거). 꼬리질문·재질문 답변이 낮으면 재질문 없이 다음 주제 {변경 11/9} |
| 그 밖 | 다음 주제 본 질문 |

기준 70·40점은 공고별 설정(`follow_score`·`retry_score`)이고, DB가 재질문 기준 < 꼬리질문 기준을 강제합니다. 관련성은 nli 컨테이너의 CE(bge-reranker-v2-m3) 점수로 재고, 점수에는 더하지 않고 분기에만 씁니다. nli 컨테이너가 응답하지 않으면 점수만으로 정합니다.

## 주제 점수
주제마다 T = S(도달 깊이) + 40 × 평균 점수 / 100. S는 깊이 0 = 0, 1 = 30, 2 = 60이라 깊이 들어갈수록 높고, 최대 100입니다. 같은 프로젝트를 다시 물으면 다른 주제로 셉니다(예: 톡허브 1·톡허브 2).

## 실제 흐름 예시 (김하늘 시연, 11/17)
실제 모델로 처음부터 끝까지 돌린 응시입니다. 답변은 '잘 준비한 지원자' 예시 답변을 TTS로 읽혀 실제 STT를 거쳤습니다.

|---|---|---|---|---|

| 2 | 비기술 · 결핍 가치 (정직) | Claude Sonnet 5.5 | 의견 | 다음 |
| 3 | 톡허브(상담 채팅) 본 질문 (코딩 약점 BFS·해시), tier 3 | Claude Sonnet 5.5 | 92 | 꼬리질문 |
| 4 | 꼬리질문 깊이 1, tier 2 문서 | qwen3:4b (사내) | 95 | 꼬리질문 |
| 5 | 꼬리질문 깊이 2, tier 1 문서 | qwen3:4b (사내) | 95 | 다음 주제 (깊이 2 끝) |
| 6 | 레이크하우스(데이터) 본 질문, tier 3 | Claude Sonnet 5.5 | 84 | 꼬리질문 |

## 한 문항 처리 순서
1. **질문 제시:** 미리 만든 Supertonic 음성을 재생하고 같은 문장을 화면에 띄웁니다. 번호와 남은 시간을 함께 보여 줍니다. 생각 시간에는 다시 듣기와 글자 크기 조절이 됩니다. {신규 11/12}
2. **생각 시간:** 비기술 10초, 기술 20초(설정값). 질문 음성이 끝난 뒤부터 셉니다. {변경 11/10}
3. **녹음:** 음성만 녹음합니다. 최대 3분, '답변 끝'을 누르면 끝납니다. 재녹음은 없습니다. 5초 침묵 자동 제출은 생각하느라 멈춘 답변이 잘려서 없앴습니다. {변경 11/11}
4. **업로드:** 공유 볼륨(`/audio`)에 올리고, 실패하면 3번까지 다시 보냅니다.
5. **STT:** stt 컨테이너가 텍스트로 바꾸고, 바로 음성을 지우고 삭제 시각을 남깁니다.
6. **인식 글 확인:** 지원자가 인식된 글을 보고 틀린 곳만 고쳐 '완료'를 누릅니다(글자 차이 30%까지, 60초 지나면 원본 그대로). 원본과 수정본을 모두 남깁니다. {신규 11/11}
7. **판정:** 개인정보를 가린 텍스트로 판정합니다. 30초 넘으면 대체 모델, 60초 넘으면 점수를 보류하고 다음 주제로 넘어갑니다(면접은 멈추지 않음). {변경 11/9}
8. **다음 결정:** `next_action`으로 정하고, 꼬리질문·재질문이면 그 자리에서 만듭니다. 본 질문은 미리 만들어 둔 것을 씁니다. {변경 11/10}
9. **알림:** SSE로 다음 질문을 보냅니다.

## 그래프 구조 {신규 11/9}
- **메인 그래프 (지원 건 1개 = thread 1개):** 1차 서류(검색 → AI 의견 → 코드 검증 → 담당자 판단) → 응시 안내 → 지원자 접속 → 코딩 1·2번 → 코딩 3번 준비 → 코딩 종료 → 점검·본인 확인 → 면접 그래프 대기 → 최종 선발(담당자) → 끝.
- **면접 그래프 (응시 1회 = thread 1개):** setup → generate → guard → ask(지원자 답 대기) → evaluate → save → decide → (10문항까지 반복) → finish → 최종 평가 → 5검사 → report → 담당자 확정 대기.
- 사람의 판단과 외부 사건(지원자 접속, 코딩 제출)이 오는 곳에서 멈추고(interrupt), 같은 thread로 재개합니다. 진행 상태는 PostgreSQL에 저장해 서버가 다시 켜져도 이어집니다.
- 판단은 사람, DB 쓰기·상태 변경은 코드(노드), 글은 LLM. 진행 결정은 `next_action`만 씁니다.

## 검색 구성 (`retrieve()`)
1. **조건 필터:** 단계·부서·직급·난이도 대역·tier로 거릅니다.
2. **하이브리드 검색:** BM25(kiwipiepy 0.24.1 형태소) ∥ bge-m3 벡터를 함께 돌립니다.
3. **합치기:** RRF(k = 60)로 순위를 합쳐 상위 k개(본 질문 1·꼬리질문 2)를 근거로 씁니다.
4. **재정렬:** 원본의 bge-reranker 재정렬(0.6 이상)은 2차 면접에서 쓰지 않습니다. 절대 점수 관문 없이 RRF 순위를 그대로 쓰고, CE는 답변 관련성 판단에만 씁니다. {변경 11/5}

## 질문 미리 만들기 {신규 11/10}
면접 중 대기 시간을 줄이려고 본 질문은 미리 만듭니다.
- **1차 합격 즉시:** 1·2번 + 기술 본 질문 후보(4~10번)를 질문 은행에서 만들어 검증 → `prepared_question`.
- **코딩이 끝나는 즉시:** 3번(코딩 약점 본 질문)을 만들어 검증.
- **면접 중:** 꼬리질문·재질문만 답변을 보고 만듭니다.
- **검증:** 길이, 지시문 베끼기, 근거 금지어, 개인정보, 문서 번호 노출, 근거 청크(tier 3, internal 아님), 다른 질문과 중복. 떨어지면 1번 다시 만들고, 또 떨어지면 은행의 기본 질문(이미 검증됨)을 씁니다.

## 질문 방어 검사
- **모든 질문:** 근거 청크의 `forbid` 단어 검사. 들어 있으면 1번 고쳐 쓰고, 그래도 남으면 코드가 가립니다.
- **꼬리질문:** 꼬리질문이 전제한 내용이 답변과 맞는지 NLI(mDeBERTa)로 봅니다. 인용 확인 → 모순 ≥ 0.3이면 탈락 → 함의 ≥ 0.6이면 통과 → 애매하면 사내 LLM이 판단. 탈락하면 1번 고치고, 또 탈락하면 점수가 높은 쪽을 쓰고 '신뢰도 낮음'으로 표시합니다. {변경 11/9 재정렬 점수 → NLI}
- 질문마다 근거 청크 id(`source_doc_ids`), 가장 낮은 tier(`min_tier`), 검사 결과(`rag_check`·`defense`)를 남깁니다.

## 모델 경로
- 근거에 tier 1·2 문서가 하나라도 있으면 사내 모델(Ollama qwen3:4b)만 씁니다. tier 3·0만이면 외부 모델(Claude Sonnet 5.5, 대체 Haiku 5.5)을 씁니다.
- 국외 전송 동의는 응시 필수가 되었습니다(활동다이어그램 1109). {변경 11/9 선택 → 필수}
- 코드가 막습니다: tier 1·2 프롬프트를 외부로 보내려 하면 호출 전에 멈춥니다(`assert_external_ok`).

## LLM 호출 관문 (`api/llm_gate.call`) {신규 11/9}
모든 LLM 호출은 이 함수 하나를 지납니다.
1. 프롬프트 조립 (`api/prompts/*.md`, 빈 변수가 있으면 호출 전에 멈춤, 파일 해시를 프롬프트 버전으로 기록)
2. 지원자 개인정보 가림 — 이름·학교·주소·연락처·이메일. 면접 답변(STT) 안에 나온 것까지 가립니다. {변경 11/12}
3. 경로 결정 (tier) → 외부로 보낼 때는 누출 검사: tier 1·2 본문·금지어·개인정보가 있으면 가리고 1번 다시 검사, 그래도 걸리면 사내 모델로 돌립니다.
4. 호출: 30초 넘으면 대체 모델, 60초 한도. 연결 끊김은 3번 재시도, 인증 오류(401·403)는 재시도 없이 운영자 알림 + 사내 모델.
5. 형식 오류면 오류 내용을 붙여 1번 다시 요청합니다.
6. 사내 모델에는 글 칸 길이를 고정한 형식을 씁니다(판정 이유 ≤200자, 질문 ≤150자 등). 작은 모델이 이유를 길게 쓰다 출력 제한에 잘리던 문제를 Ollama가 생성 단계에서 막습니다. {신규 11/16}
7. 호출 기록 `llm_call`: 목적·프롬프트 버전·제공자·모델·tier·토큰·시간·성공 여부. 프롬프트 본문은 남기지 않습니다.

## 난이도와 생성 시점
- **난이도 대역:** 코딩 등급 골드2·3 = 상, 골드4 = 중, 골드5·실버1 = 하. 면접 시작 때 `interview_session.ct_band`에 고정합니다.
- **고정:** 약점 요약·인계 데이터·난이도 대역·모델은 시작 때 응시에 복사해 면접 도중 바뀌지 않게 합니다.

## 최종 평가
- **주제 점수 → 내용 60:** 주제 점수 평균 × 0.6 (임시 산식).
- **언어 30:** 답변별 언어 3항목 합의 평균.
- **비언어 10:** (시간 안에 마침 0.5 + (1 − 침묵 비율) 0.5)의 평균 × 10 (임시 산식).
- **5검사:** 1~4번은 코드가, 5번(근거–점수 정합)은 평가 모델과 다른 사내 모델(qwen3:1.7b)이 봅니다. 실패하면 1번 재평가(v2), 또 실패하면 담당자 알림.
- **의견(점수 아님):** 프로젝트 적합성(지금 투입 가능한지)·확장성(다른 프로젝트로 옮겨도 가능한지).
